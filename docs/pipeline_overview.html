particle-sim 전체 흐름 — DL1 · compare · DL2

작성 2026-10-20 · 기준 commit: particle-sim-dl1 ff1188d, particle-sim-compare 8bc937b, particle-sim-dl2 63e806e
같은 문서가 세 저장소의 docs/pipeline_overview.html에 들어 있습니다. 세부 규칙은 각 저장소의 docs/USAGE.md와 compare의 docs/handoff/commands.md가 기준입니다.

검증 범위: 세 저장소 모두 합성 자료로만 검증됐습니다. 실제 자료에서의 성능, Windows에서의 DL1·DL2 전체 연동은 아직 확인되지 않았습니다. 창 크기, grid, 흔들림 폭, epochs 같은 값에는 기본값이 없습니다. 이 문서의 숫자는 형식을 보여 주는 예시이며 권장값이 아닙니다.

1. 전체 흐름

네 단계로 진행합니다. DL1 → compare(1차) → DL2 → compare(2차). 저장소끼리는 코드로 서로 부르지 않습니다. 각 단계는 schema가 정해진 JSON 파일로 결과를 넘깁니다.

① DL1 — 제품 단위

  • 새 제품과 원본 형상·전극 연결이 비슷한 기존 제품을 찾습니다
  • 입력: 모델별 전극·CNT PNG
  • 출력: 비교군 후보 제품 목록 dl1_search.json
→

② compare 1차 — 수치·ROI

  • reference/target 수치 비교와 제품별 전극 수 지도
  • 검토 위치(ROI) 내보내기 review_rois.json
  • 두 제품 취약 영역 → 질의 ROI·색인 export (candidates)
→

③ DL2 — 위치(ROI) 단위

  • ROI 하나와 국부 구조가 비슷한 다른 위치를 찾습니다
  • 검색 범위: DL1 비교군(cohort) 안
  • 출력: dl2_index.json, dl2_search.json. 학습이 없는 NCC 기준선도 함께 냅니다
→

④ compare 2차 — 확정·결합

  • 사용자가 후보 쌍을 확정합니다 → roi_correspondence_v1
  • 대응 위치의 국부 ΔCA (compare-windows)
  • DL 결과를 원본 CA 옆에 붙입니다 (dl_results), HTML 보고서

단계 사이에 넘어가는 파일

보내는 쪽 → 받는 쪽파일 / schema쓰임
DL1 → DL2cohort.json (제품 id 배열, 사용자가 DL1 결과에서 작성)DL2 검색 주 결과의 대상 제품
DL1 → comparedl1_search.json어떤 제품끼리 비교할지(reference/target) 정하는 근거. ④에서 dl_results seal --dl1로 붙입니다
compare → DL2review_rois.json (review_roi_v1) + 원본 assetDL2 학습·색인·검색의 입력. DL2 입력은 이것 하나입니다
compare → DL2pairs_ids.json (roi_correspondence_v1), dl2_relations.json (roi_relations_v1)위치 평가의 정답, 학습 라벨(선택)
DL2 → comparedl2_search.json, dl2_index.json, NCC baseline*.json후보 확정(confirm-pairs --match), 수치 결합(dl_results)
연결 규칙
  • DL2는 export의 producer_commit(40자리 hash)을 확인합니다. compare를 git 밖 사본으로 설치해 producer_commit=null이 되면 기본적으로 거부합니다. 이때는 commit을 명시하거나 --allow-unversioned-producer를 붙입니다.
  • hotspot·CA·fab 값은 DL1·DL2 어느 쪽에도 입력으로 넣지 않습니다. 넣으면 오류가 납니다.
  • 결합할 때 source_identity가 전부 맞아야 연결됩니다. case_id만 같아서는 연결되지 않습니다.

2. 학습 방법 — DL1과 DL2

DL1DL2
찾는 것비슷한 제품비슷한 위치(ROI)
학습 단위제품 전체 이미지. 전극 × layer별 요소와 CNT, valid 채널ROI 하나를 가까운(near)·넓은(wide) 두 창으로 자른 원본 형상. 전극 역할·layer, CNT/VIA
사전학습있음, 선택: psdl1.pretrain. 라벨 없이 train·validation 제품의 요소 이미지에서 가린 패치를 복원합니다(FCMAE dense 근사). 결과 backbone.pt를 본 학습 --weights에 넣습니다. 효과가 있는지는 --weights 없이/있이 학습해 validation에서 비교해야 합니다별도 단계 없음. 본 학습 자체가 자기지도입니다. 미리 학습된 가중치 없이 처음부터 학습합니다
본 학습지도 대조학습. relations.csv의 similar/different 쌍을 씁니다. 적지 않은 쌍은 "모름"으로 학습에서 빠집니다. 라벨이 없으면 --unlabelled-negatives(실험 옵션)가 필요합니다자기지도. 같은 ROI의 중심을 jitter_xy_um만큼 흔들어 두 view를 만들고, 두 view가 가까워지도록 배웁니다(alignment + variance + covariance 손실). labels.json은 선택이며 있으면 지도 손실을 더합니다
쌍이 필요한가제품 쌍 라벨이 필요합니다. 초안은 relations_draft 또는 screen_relations로 만들고 사용자가 확정합니다필요 없습니다. 제품 하나만으로 ROI를 내보내 학습할 수 있습니다. 쌍은 평가에만 필요합니다
분할split.json (dl1_split_v1): 제품 → train/validation/test. 같은 lineage는 한 구획에만 둡니다split.json: ROI → 구획, lineages.json: 제품 → 계열. 같은 계열·겹치는 ROI는 한 구획에만 둡니다. train에 서로 다른 위치가 2개 이상 있어야 합니다
사용자가 정할 값candidate grid, epochs/batch/lr/seed, 라벨near/wide 창 크기, pitch, resampling, jitter, core, intermediate layer 정책, max_pair_attempts, 손실 가중치, epochs/batch/lr/seed
checkpointdl1.pt(+ history.json, split.json). --resume 가능dl2.pt. epoch마다 원자적으로 교체됩니다. config의 epochs를 늘리고 --resume
GPU--device cuda 선택--device cuda (train/index/search). CPU로 자동 전환하지 않습니다

3. 단계별 명령 · 입력 · 출력

각 표의 "하는 일" 열은 그 명령이 무엇을 하는지 한 줄로 적은 것입니다. 아래 명령은 Git Bash 기준이고 $PY는 각 저장소 venv의 python입니다. CMD 형식은 compare docs/handoff/commands.md에 있습니다. 경로는 실제 위치로 바꾸세요.

① DL1 (particle-sim-dl1)

#하는 일명령입력출력
1PNG 폴더를 읽어 형식을 검사하고 CNT 형상 미리보기를 만든다psdl1.import_png --root R --out DPNG 폴더 <모델>/<전극>/<순번>-<layer>.png, <모델>/cno/…. 0.1 µm/pixel, 흰 바탕에 검은 패턴import-report.json, preview.html
2후보 grid마다 가는 선이 사라지거나 끊기는지 검사해 grid를 고른다psdl1.import_png … --inspect-grids G1 G2후보 grid 숫자grid별 가는 선·끊김 경고, 진단 PNG
3고른 grid와 계보 정보로 학습용 manifest와 NPY를 만든다psdl1.import_png … --export --metadata M --candidate-grid G계보 metadata(dl1_png_metadata_v1: lineage_id, design_version)manifest.json(dl1_shape_v1_draft), NPY
4내보낸 묶음이 온전하고 격자 조건을 만족하는지 확인한다psdl1.import_png --verify-bundle D, psdl1.data manifest.json --report r.json3의 결과확인 결과, 격자 보고서
5학습용 제품 쌍 라벨(similar/different) 초안을 만든다psdl1.relations_draft / psdl1.screen_relations (선택)manifest, split(, groups.json)relations.csv 초안, *.review.csv|html, scores.csv, summary.json
6라벨 없이 백본만 미리 학습한다psdl1.pretrain --manifest … --split … --out P (선택)manifest, split (test는 쓰지 않음)P/backbone.pt, history.json, cache/
7제품 임베딩 모델을 학습한다psdl1.train --manifest … --split … --relations … --out T [--weights P/backbone.pt]manifest, split, relationsT/dl1.pt, history.json, split.json
8새 제품과 비슷한 기존 제품을 찾아 순위를 낸다psdl1.search --ckpt T/dl1.pt --query-manifest Q --query ID --candidates-manifest C --topk K --out s.jsonquery manifest(같은 grid로 export), 후보 manifestdl1_search.json: score/rank/excluded/grid/fingerprint
9정답 쌍으로 모델과 기준선의 검색 성능을 평가한다psdl1.evaluate … --relations … --out e.json승인된 relations (없으면 보류)평가 JSON (모델 vs 정규화 이미지 기준선)

③ DL2 (particle-sim-dl2)

#하는 일명령입력출력
1ROI 목록과 원본 asset을 검증하고 메모리 사용량을 확인한다psdl2.data review_rois.json --assets-root A [--max-asset-memory-mb N]compare의 review_rois.json, 원본 asset검증 요약 JSON(stdout): ready/blocked 수, 사유, asset_memory
2ROI 위치 임베딩 모델을 자기지도로 학습한다psdl2.train review_rois.json --assets-root A --config config.json --lineages lineages.json --split split.json [--labels labels.json] --out runs/dl2.pt --device cudaexport, psdl2_run_v1 config, lineages, split, (labels)dl2.pt, 결과 JSON(stdout: history, 거부 사유 통계), 진행 JSON 줄(stderr)
3후보 ROI 전체를 벡터로 바꿔 색인을 만든다psdl2.index candidates/review_rois.json --assets-root A --checkpoint dl2.pt --out dl2_index.json후보 ROI exportdl2_index.json (psdl2_index_v2): ROI별 embedding, source_identity, coverage
4query ROI 하나와 비슷한 위치를 비교군 안에서 찾는다psdl2.search query/review_rois.json --roi-id ID --checkpoint dl2.pt --index dl2_index.json --cohort cohort.json --topk K [--expand] --out dl2_search.jsonquery export, 색인, DL1 비교군 cohortdl2_search.json: primary(cohort 안) / supplementary(--expand) / no-match
5라벨이 있을 때 검색 결과를 평가한다psdl2.evaluate results.json --k K --split split.json --partition test --labels labels.json검색 결과 배열, 라벨평가 JSON(stdout)
6학습 없는 NCC template matching으로 기준선 후보를 낸다psdl2.baseline_ncc --query-export Q --index-export C (--correspondence P | --all-ready --max-memory-mb N) --window-um W --topk K --out baseline.json [--sheet-dir S]query/후보 export (학습 없음)baseline.json, 검토 시트 S/sheet.html
7DL2와 기준선 결과를 정답 위치 기준의 같은 지표로 비교한다psdl2.eval_position (--search … | --baseline …) --correspondence pairs_ids.json --hit-tolerance-um T --k K --out eval.json검색/기준선 결과, 정답 쌍top-1 hit rate, hit rate@k, top-1 거리

④ compare 2차 (particle-sim-compare)

#하는 일명령입력출력
1NCC/DL2 후보 중 사용자가 accept한 쌍만 대응 위치 파일로 확정한다simcompare confirm-pairs --config cfg.yaml --candidates CAND --match reference_to_target=ncc.json --list → decisions.csv 작성 → … --decisions decisions.csv --labelled-by USER --mutual-tolerance-um T --out CONF②-5 candidates 출력, NCC/DL2 매칭 결과, 사용자 accept/rejectroi_correspondence.json (roi_correspondence_v1), confirmed_pairs_sidecar.json(점수), confirm_funnel.json|csv
2대응 위치의 같은 물리 창에서 국부 ΔCA를 계산한다simcompare compare-windows --config cfg.yaml --correspondence P --window-sizes 10 20 30 --out LOCAL대응 위치 쌍, 창 크기 후보local_delta.json|_rows.csv|.html, window_sensitivity.*
3ROI의 원본 수치 문맥을 모은다simcompare.dl_results context SOURCE_ROOT review_rois.json --asset-manifest M --out numeric_context.json수치 원본, ROI exportnumeric_context.json
4DL1·DL2 결과를 hash·fingerprint와 함께 묶어 봉인한다simcompare.dl_results seal --context … --dl1 dl1_search.json --dl1-fingerprint F --dl1-bindings b.json --dl2 dl2_search.json --dl2-cohort cohort.json --dl2-index dl2_index.json --dl2-expected dl2_expected.json --pending-gates g.json --out exchange.jsonDL1·DL2 결과, 승인한 fingerprintexchange.json (sidecar. 원래 DL 결과 JSON은 수정하지 않음)
5봉인한 결과를 원본 수치 옆에 나란히 붙인다simcompare.dl_results read exchange.json --out joined.json4의 결과joined.json: DL score/scope/coverage와 원본 수치를 나란히
6앞 단계 결과를 HTML 보고서 하나로 모은다simcompare report --compare-dir CMP [--map-dir --windows-dir --rois-dir --candidates-dir --confirm-dir] --out REP앞 단계 출력 폴더HTML 보고서 한 파일

4. 운영 메모

  • DL2 학습 자료: DL2가 학습·검색하는 위치는 compare가 내보낸 ROI뿐입니다. 학습·색인에 넣을 제품은 모두 compare에서 export해야 합니다. 제품 하나씩으로도 되며 비교 제품은 필요 없습니다. 다만 수치 자료(case)가 없는 위치는 blocked 됩니다.
  • export는 파일 하나: DL2 train과 index는 export 파일을 하나만 받습니다. 여러 제품을 한 export로 묶으려면 merge-exports로 data_dir을 합친 뒤 내보내는 방법을 생각할 수 있습니다. 이 방법은 아직 확인하지 않았습니다.
  • 색인과 검색은 같은 PC에서: compare가 결과를 읽을 때 점수를 색인으로 다시 계산해 대조합니다.
  • DL1 이름 제한: 학습에 없던 전극·layer 이름을 가진 제품은 DL1 검색에서 unavailable 또는 excluded가 됩니다.
  • 점수의 의미: 유사도 점수는 원인 판정이나 위험 예측이 아닙니다. CA 값은 항상 원본 결과에서 읽습니다.
  • 폐쇄망에서 정할 것: DL1 grid, DL2 창·pitch·jitter·core, 라벨 형식과 수락 기준(G6), ΔCA 창 크기(G4).
